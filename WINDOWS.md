# FramePilot для Windows: состояние порта 0.15.2

Подготовлены общий код, отдельный захват окон через Qt, нейросетевой детектор лица YuNet и команды сборки. Это **исходники для предварительной Windows-версии**. Готовый проверенный Windows EXE в этот выпуск не входит: в текущей среде доступен только Mac.

В 0.15.1 исправлены поиск файла настроек OBS, ошибки получения списка окон, повтор старого кадра после остановки захвата и сохранение исходного имени камеры при нескольких запущенных копиях. При закрытии, сворачивании или смене процесса выбранного окна захват прекращается с сообщением; после восстановления окна его можно возобновить. Эти проверки выполнены с подставными системными интерфейсами на Mac; фактический Windows API ещё требует испытаний. [Полный отчёт](./AUDIT.md).

В 0.15.2 дополнительно защищены исходники других заданий очереди, сохранение проекта, смена камеры и источника. Исправлены масштабирование панорам и округление размера очень узких кадров. Подробности — в [повторном отчёте проверки](./AUDIT-0.15.2.md).

Первой целью выбран Windows 11 x64 с Python 3.13 x64. Windows ARM64 и запуск под Wine не проверены.

## Своё название виртуальной камеры

После сборки откройте **«Вывод → Вывод в OBS → Имя виртуальной камеры…»**. Эта же команда есть в меню **«… → Имя виртуальной камеры (Windows)…»** и на странице OBS в мастере подключения.

1. Установите OBS обычным установщиком Windows, если камера ещё не установлена.
2. Введите своё имя, например **«Камера студии»** или **«FramePilot Camera»**.
3. Нажмите **«Переименовать»** и разрешите изменение в системном окне UAC. Если у вашей учётной записи нет административных прав, Windows может запросить учётные данные администратора. В FramePilot пароль не вводится и не сохраняется.
4. Перезапустите принимающую программу и выберите новое имя в её списке камер. Иногда требуется перезапуск FramePilot из-за кэша списка устройств.

Имя можно менять повторно. **«Вернуть исходное имя»** восстанавливает имена, прочитанные перед первым изменением; последующие переименования эту копию не заменяют. Копия сохраняется в файле `camera-name-original.json` рядом с настройками FramePilot в профиле пользователя.

Меняются только отображаемые имена существующей стандартной камеры OBS в установленных 32- и 64-битных регистрациях. GUID камеры, DLL модуля и поток видео сохраняются. Новая камера или драйвер не создаются; для видео по-прежнему нужен OBS. В мастере подключения переименованное устройство определяется по идентификатору и подтверждённым именам регистрации.

Операция читает текущие значения до и после записи. Если OBS успел изменить регистрацию, действие останавливается. При ошибке записи выполняется откат сделанных изменений; неполный откат показывается как ошибка. Административный помощник принимает только имена и ожидаемое состояние, не принимает произвольные пути реестра и не записывает файлы от имени администратора.

Поддерживается стандартная машинная установка OBS. При отдельной пользовательской COM-регистрации, неизвестном модуле или неполной регистрации изменение блокируется с сообщением. Обновление/переустановка OBS может вернуть название OBS Virtual Camera. Приложения могут кэшировать имена; совместимость с конкретным приёмником требует проверки.

**Проверка 0.15:** логика переименования/восстановления, ошибки записи, отказ UAC и GUI проверяются на тестовом реестре под macOS. Реальное изменение реестра и системное окно UAC на Windows в этой среде не проверены. Самопроверка сборки не меняет имена камер автоматически.

## Что перенесено

- Интерфейс, видео и фото JPEG/PNG, выбор области предмета, кадрирование, маски рамок, сценарии и MP4.
- Лица и ориентиры глаз: локальный YuNet через OpenCV DNN. Модель включена в исходники и приложение, лицензия MIT и контрольная сумма прилагаются; во время работы сеть для модели не нужна.
- Выбор внешнего окна и получение его кадров через `QWindowCapture`/FFmpeg. Окна собственного процесса исключаются из списка. Запоздалые кадры предыдущего источника отбрасываются.
- Локальный поток и настройка Browser Source/OBS Virtual Camera используют общий протокол OBS WebSocket.
- Физическая камера через Qt; её доступность и драйвер проверяются на компьютере пользователя.

## Что пока отсутствует или требует реального Windows-теста

Полный рабочий стол не предлагается в первом Windows-порте, чтобы не включать рекурсивный захват предпросмотров. Доступен путь захвата выбранного окна. Режимы поиска фигуры человека и удаления фона людей, использующие Apple Vision, в Windows отключены. Фото с PNG-прозрачностью и маски композиции работают независимо от этого ограничения.

Нативные Windows-захват, камера, кодеки и реальная OBS Virtual Camera ещё не проверены на Windows. Защищённые, свёрнутые и некоторые аппаратно рисуемые окна могут быть недоступны для захвата. Результат проверки с Mac не заменяет эту проверку. Автоматический поиск геометрической рамки не определяет назначение любого элемента интерфейса и не вставляет изображение прямо в произвольный чужой интерфейс.

## Запуск из исходников

1. Распакуйте весь исходный проект в папку на Windows.
2. Установите Python 3.13 x64 с официального python.org и Python Launcher (`py`).
3. Запустите `Start FramePilot Windows.cmd`.

Команда создаст `.venv-windows`, установит зависимости и откроет приложение. Для установки зависимостей нужен интернет. Xcode и Apple Developer Program не требуются.

## Сборка переносимого приложения

Запустите `Build FramePilot Windows.cmd`. Сборка:

1. Проверяет архитектуру Python и устанавливает зависимости сборки и тестирования.
2. Запускает общий набор тестов для Windows с YuNet. Журнал и JUnit-отчёт сохраняются в `test-results\windows-release`.
3. Создаёт `dist\FramePilot\FramePilot.exe` вместе с библиотеками и проверяет, что получен Windows x64 EXE.
4. Запускает самопроверку фото, лица, интерфейса, локального видеопотока, воспроизведения и MP4; отчёт — `test-results\windows-release\windows-check.json`. Проверяются версия, платформа Windows и результат каждого обязательного этапа. Старый отчёт не может подтвердить новую сборку.
5. Только после успешных тестов и самопроверки создаёт `dist\FramePilot-0.15.2-Windows-x64.zip` и SHA-256. Архив включает runtime, инструкцию запуска и отчёты QA. При ошибке существующий ZIP не заменяется.

Команда для уже подготовленного окружения: `python tools\windows_release.py`. На macOS она завершится отказом и не создаст Windows EXE.

## Автоматическая сборка на Windows через GitHub

Подготовлен `.github/workflows/windows.yml`: ручной запуск **Actions → Windows build and checks → Run workflow**, Python 3.13 x64, Windows runner `windows-2022`. После успешного выполнения в артефакте **FramePilot-Windows-x64** находится ZIP с приложением; **Windows-checks** содержит подробные отчёты. Для этого нужен репозиторий в вашем GitHub и доступ к Actions. Файлы в GitHub из этой среды пока не загружались, workflow не запускался.

Облачный Windows runner проверяет сборку, обработку файлов, UI, локальный поток и экспорт. Это не подтверждение физических камер, интерактивного захвата окна, OBS, UAC/реестра или Android-приложений на Windows 11. Такие этапы требуют отдельного запуска на Windows с рабочим столом и установленным OBS.

## Что проверено при подготовке Windows-сборки

На Mac с принудительным YuNet прошли **200 тестов общего набора**, два теста Apple Vision исключены. Исправлены два тестовых стенда захвата: они теперь явно подставляют владельца тестового окна и не обращаются к настоящему Win32 для выдуманных HWND. Проверены защита от чужого/32-битного EXE, неполной самопроверки, старого отчёта и повреждённого архива. Это проверка кода сборки и общего движка на Mac; готовый Windows EXE ещё не собран.

Передавать другому компьютеру нужно весь ZIP. На компьютере получателя Python не требуется. Скрипты не выполняют публикацию или подпись приложения; SmartScreen может отображать неподписанную сборку.

## Проверка на Windows перед выпуском

Проверьте обычный запуск из распакованной папки на компьютере без Python. Затем отдельно: окно с движением/изменением размера, переключение окон и закрытие источника; физическую камеру; ролики пользователя; передачу видео в OBS и приём OBS Virtual Camera в нужном приложении. Начните с 1280×720, 30 FPS, измерьте реальную частоту/задержку на этом устройстве. Самопроверка не заявляет прохождение этих внешних этапов.

На Mac общий путь без Apple Vision проверяется командой:

```sh
FRAMEPILOT_VISION_BACKEND=yunet .venv/bin/python -m framepilot --portable-self-test --report test-results/portable-check.json
```

В ветке Mac также проверена логика переключения Windows-захвата на тестовом бэкенде. Это проверка защиты от запоздалых кадров, а не проверка Win32 или Qt-захвата в Windows.
