# FramePilot

Приложение для Mac: **видео, фото JPEG/PNG, камера или экран/окно → лицо, человек или выделенная область → до четырёх рамок → OBS Virtual Camera, MP4 или изображение**. Обработка локальная, без загрузки видео в облако.

## Установить готовое приложение

Откройте [FramePilot-0.15.2-AppleSilicon.dmg](./dist/FramePilot-0.15.2-AppleSilicon.dmg), перетащите **FramePilot** на ярлык **«Программы»**, затем запустите приложение из этой папки. После копирования образ можно извлечь. Устанавливать Python, зависимости или Xcode и выполнять команды в терминале не нужно: всё необходимое для работы приложения находится внутри `.app`.

Для начала нажмите «Открыть файл» либо выберите пример в левой панели. Доступ к камере и записи экрана нужен только при использовании соответствующих источников. OBS требуется для передачи через OBS Virtual Camera; открытие файлов, обработка и сохранение работают без него.

## Windows 0.15.2: своё имя виртуальной камеры

Добавлена автоматическая Windows-сборка с тестами, проверкой готового EXE и отчётами QA: `Build FramePilot Windows.cmd` либо ручной workflow `.github/workflows/windows.yml`. Для фактической сборки нужна Windows или Windows runner; в текущей среде Windows недоступна. [Порядок сборки и пределы проверки](./WINDOWS.md).

В Windows добавлено окно **«Вывод → Вывод в OBS → Имя виртуальной камеры…»**; команда также есть в верхнем меню «…» и мастере подключения. Введите своё название, нажмите **«Переименовать»** и разрешите изменение в системном окне Windows. Имя можно менять повторно. **«Вернуть исходное имя»** использует копию, сохранённую перед первым изменением.

Обновляются только имена стандартной установленной камеры OBS для 32/64-битных приложений; GUID, модуль и поток сохраняются. При ошибке записи выполняется откат, а результат подтверждается повторным чтением регистрации. Переименованная камера определяется в мастере по идентификатору и подтверждённым именам, поэтому слово OBS в новом названии не требуется. Перезапустите принимающие приложения после изменения имени; обновление OBS может вернуть прежнее название.

[Исходники Windows 0.15.2](./dist/FramePilot-0.15.2-Windows-source.zip), [инструкция и ограничения](./WINDOWS.md). Mac-установщик и исходники Windows обновлены до 0.15.2. Функция проверена на тестовом реестре и UI под macOS. Реальный реестр Windows и запрос UAC ещё требуют проверки на Windows; сборка и самопроверка не переименовывают камеры автоматически.

## Новое в 0.14: детектирование и подготовка Windows-порта

**Рамки.** Поиск учитывает тонкие и прерывистые границы, сравнивает обычные и слабоконтрастные контуры. Область поиска теперь действительно обрабатывается как отдельное изображение: небольшая рамка не отбрасывается из-за размера всего окна. Допускаются рамки почти во всё окно; граница самого снимка исключается. Слишком вытянутые полосы интерфейса с отношением сторон больше 8 не предлагаются автоматически. Для намеренно узкой рамки укажите область поиска или выделите её вручную. Обычный интервал запроса захвата сокращён с 600 до 250 мс; быстрый остаётся 120 мс, подтверждение требует двух снимков. Это интервалы запросов, а не гарантированная задержка всей цепочки.

**Лицо.** На Mac основной детектор Apple Vision анализирует кадр до 960 пикселей по длинной стороне, при отсутствии результата используется локальная нейросеть YuNet. Если клик или ранее выбранное лицо не подтверждены глобальным поиском, выполняется дополнительный поиск в увеличенной локальной области, даже если в кадре найдено другое лицо. Прежние ограничения переключения между людьми сохраняются. Обнаружение лица не является биометрической идентификацией. Трекер выделенного предмета по-прежнему работает по движению и образцу, универсальный детектор любого предмета не заявлен.

YuNet входит в сборку, MIT-лицензия и SHA-256 прилагаются. Загрузка модели во время работы не требуется. [Официальная модель и ограничения](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet). Проверены лицо/глаза на уменьшенном и затемнённом тестовом портрете, локальный поиск по клику, тонкие, пунктирные, слабоконтрастные, крупные рамки и маленькая рамка в ROI. Эти проверки не заменяют разбор реального пользовательского ролика и окна.

**Пример ошибки.** В верхнем меню «…» нажмите «Сохранить пример ошибки (кадры + параметры)…». В выбранной локальной папке сохраняются видимый исходник, снимок окна назначения, результат, интерфейс и JSON параметров. Исходный ролик целиком не копируется, пароль OBS не сохраняется. Ничего автоматически не отправляется.

**Windows.** Подготовлены отдельный захват окон через Qt, общий детектор YuNet, команды запуска/сборки и самопроверка без Apple Vision. [Инструкция и ограничения Windows](./WINDOWS.md), [исходники Windows-порта](./dist/FramePilot-0.15.2-Windows-source.zip). Готового проверенного Windows EXE пока нет: Windows-сборка и испытания требуют Windows. В первом порте отключены Apple Vision-сегментация людей и поиск фигуры человека; полный рабочий стол не предлагается. Проверка общего движка на Mac с YuNet не считается проверкой Windows-захвата, драйверов камеры или OBS в Windows.

Замер на M5 после прогрева, по 60 повторов: поиск рамки на синтетическом 1280×720 — в среднем 1,99 мс, p95 2,29 мс; Apple Vision на портрете 512×512 — 4,39 мс / 5,00 мс; YuNet — 4,13 мс / 4,92 мс. Замер исключает декодирование, рендеринг, захват окна, OBS и принимающее приложение. [Отчёт](./test-results/benchmark-detection-0.14.json).

Проверка 0.14 на M5: **226 автотестов** прошли за 33,63 с. Самопроверка готовой Mac-сборки — 10,40 с; отдельная самопроверка этой сборки с YuNet вместо Apple Vision — 0,63 с. [Полный прогон](./test-results/tests-0.14.log), [проверка Mac-сборки](./test-results/bundle-check-0.14.json), [общий движок в сборке](./test-results/bundle-portable-0.14.json). В этом выпуске Windows EXE и нативный захват на Windows не испытывались.

## Новое в 0.13: фото и исправления подключения

**Фото JPEG/PNG.** Откройте файл или перетащите его на окно. Фото сначала показывается целиком. В разделе «Цель → Фото» доступны поиск лица, возврат к целому изображению и сохранение PNG/JPEG. Прямоугольное выделение задаёт любую область фото, включая однотонную: для статичного источника оценка движения не нужна. Работают часть области, маски, изменение рамки, предпросмотр, OBS и запись статичного изображения в MP4 без звука. Выбор сохраняется в сценариях и автосохранении. Учтены EXIF-ориентация JPEG и альфа-канал PNG. Рабочий размер ограничен длинной стороной 4096, входной — 100 Мп; поддержка HEIC, GIF и анимированных изображений не заявлена. Прозрачные области смешиваются с фоном композиции: сохранённый результат, MJPEG и OBS-выход непрозрачны.

**Передача в OBS.** Нажмите «В OBS» в верхней панели и подключитесь к локальному WebSocket. Затем выберите сцену FramePilot в OBS либо включите флажок переключения сцены и запуска виртуальной камеры. Приложение должно оставаться запущенным. При подключении браузерный источник принудительно обновляется — в том числе после неудачной загрузки до запуска FramePilot. Явно включённый локальный выход восстанавливается после перезапуска; остановка выхода запоминается. Пароль и включение камеры автоматически не восстанавливаются. Статус различает подключение к OBS и видимость источника. Механизм обновления проверен по [исходному коду OBS Browser](https://github.com/obsproject/obs-browser/blob/master/obs-browser-plugin.cpp).

Проверена реальная передача движущегося ролика в установленную OBS 33.0.1: пять различных снимков браузерного источника, сигнал без блокировки. [Отчёт OBS](./test-results/obs-video-0.13.json). Этот результат не подтверждает приём камерой в Android-приложении.

**Рамка внешнего приложения.** На шаге «Рамка» нажмите «Обновить окна», разрешите FramePilot запись экрана в macOS и выберите настоящее окно из списка. Кнопка «Разрешение записи экрана…» открывает нужный раздел настроек; после изменения разрешения может потребоваться перезапуск. Теперь предпросмотр обновляется и с ручной рамкой или выключенным автопоиском. Тестовое окно явно отмечено как демонстрация. Если контур не найден, попробуйте режим тонких рамок, ограничьте область поиска или выделите рамку вручную. Распознавание произвольного интерфейса не гарантируется; конкретное окно пользователя ещё требует проверки. Поиск рамки задаёт кадрирование; принимающее приложение должно само поддерживать источник камеры, это не прямая подмена его интерфейса.

Для разработчика: после сборки `.app` команда `.venv/bin/python tools/package_app.py` создаёт DMG и файл SHA‑256. В образе находятся приложение, ярлык «Программы» и краткая инструкция; исходный проект и виртуальное окружение в установщик не включаются.

Проверка выпуска 0.13 на этом M5: полный прогон 207 тестов и дополнительный прогон 10 тестов фото/перезапуска пройдены. Самопроверка готовой `.app` — 11,71 с, запуск с DMG только для чтения в чистом окружении — 10,80 с; подпись проверена. Самопроверка включает фото, прозрачность, JPEG/PNG, поиск лица и запись статичного изображения. [Отчёт сборки](./test-results/bundle-check-0.13.json), [проверка установщика](./test-results/installer-check-0.13.json), [тесты](./test-results/tests-0.13.log), [тесты фото](./test-results/tests-photos.log).

## Новое в 0.12: поворот части, качество кадра, восстановление и очередь

**Часть следует за поворотом.** Выделите предмет целиком, выберите «Показывать → Левая половина» или свою часть и включите «Цель → Качество и поворот → Часть следует за поворотом». Часть теперь задаётся относительно исходного выделения и перемещается вместе с его поворачивающимся четырёхугольником. Синий/жёлтый полигон на исходнике показывает точную выбранную область. Поворот самого видео сохраняется; изображение не выпрямляется. Фон внутри выбранного участка сохраняется, за его пределами — фон композиции. У каждого слота своя настройка.

Геометрия поверхности сохраняется в анализе, проектах, временных поправках и выбранной цели для восстановления/очереди. Повторный выбор по сохранённому четырёхугольнику сохраняет исходные оси части. Старые проекты открываются; если в старом анализе геометрии нет, привязка не подменяется обычной половиной текущего прямоугольника — потребуется повторный анализ от исходного выделения. При выделении новой части на повёрнутом предмете прямоугольное выделение переводится в координаты исходной поверхности; полученный участок виден полигоном. Режим рассчитан на жёсткую текстурированную область и поворот в плоскости кадра. Сильная перспектива, поворот другой стороной, деформация и произвольное движение в 3D не гарантируются. Без этой настройки сохраняется прежнее кадрирование относительно окружающего прямоугольника.

**Контроль качества кадрирования.** В разделе «Качество и поворот» показываются приблизительная видимая доля выбранной области, масштаб исходных пикселей и замечания. Обрезка более 5% области и увеличение больше 2× отмечаются; у результата появляется `!` с подробной подсказкой. Это оценка видимости прямоугольника/полигона, а не распознавание силуэта предмета или измерение резкости. Заполнение рамки и отверстия PNG-маски могут намеренно давать замечание об обрезке. «Вписать и сбросить приближение» возвращает вписывание, масштаб 1× и снимает дополнительное смещение/приближение приёмника; зеркало, поворот и видимая область камеры сохраняются. Произвольная PNG-маска может продолжать обрезать изображение.

**Восстановление файлового сеанса.** Настройки, позиция, выбранные цели, поправки и рассчитанная траектория сохраняются в фоне после изменений и периодически, раз в 30 секунд. Файл заменяется атомарно после завершённой записи; кадры видео и пароли туда не включаются. При следующем запуске в «Источник → Восстановление сеанса» доступна кнопка восстановления. Ролик восстанавливается на паузе; камера и экран автоматически не включаются. Изменённый или отсутствующий исходник не восстанавливается молча. Очередь экспорта хранится отдельно в текущем сеансе и в это восстановление не входит.

**Очередь экспорта.** Откройте первый ролик, выберите для него цели, маску и параметры, затем нажмите «Вывод → Очередь экспорта → Добавить от текущего кадра». Выберите файл результата. Повторите для остальных видео и запустите очередь. Для полного ролика подготовьте выбор с первого кадра. Каждое задание хранит свои настройки, выбранную цель/геометрию, анализ, начальную позицию и проверку исходного файла; настройки следующего ролика его не меняют. Задания выполняются последовательно. Ошибку можно пропустить или остановить очередь, отменённые/ошибочные задания можно повторить. Изменение исходника требует подготовить задание заново. Два задания с одинаковым файлом результата не добавляются; исходник не перезаписывается.

### Какие видео можно открывать

Поддержка определяется контейнером, кодеком и его профилем, а не одним расширением. Это зависит и от сборки медиакомпонентов: [Qt Multimedia](https://doc.qt.io/qt-6/qtmultimedia-index.html), [форматы FFmpeg](https://ffmpeg.org/ffmpeg-formats.html). Диалог предлагает MP4, MOV, M4V, MKV, AVI, WebM, MTS/M2TS/TS, MPEG, MXF, WMV, FLV, 3GP, OGV и DV; «Все файлы» позволяет выбрать другой контейнер. Наличие в фильтре не является гарантией декодирования.

Проверены предпросмотр Qt, чтение первого кадра FFmpeg и экспорт следующих сочетаний на локальных тестовых роликах:

| Контейнер | Кодек |
| --- | --- |
| MP4 | H.264 |
| MOV | HEVC / H.265 |
| MOV | ProRes |
| MKV | MPEG‑4 Part 2 |
| AVI | MJPEG |
| WebM | VP9 |
| MP4 | AV1 |

При открытии выполняется фоновая проверка первого кадра. В «Источник → Совместимость видео» отдельно видны результат FFmpeg и фактический результат предпросмотра Qt. Повреждённые и защищённые файлы, неизвестные профили кодеков, правильность цветового преобразования HDR/10-bit в SDR, все разновидности перечисленных контейнеров и произвольные многопоточные файлы не считаются проверенными. Обхода DRM нет. AV1 в WebM, например, не считается проверенным только потому, что прошли AV1 в MP4 и VP9 в WebM. Первокадровая проверка не подтверждает исправность всего длинного файла.

## Новое в 0.11: анализ, поправки, маски и живые источники

**Предварительный анализ ролика.** Откройте видео, поставьте на паузу, выберите цель и раскройте «Цель → Анализ ролика». Нажмите «Анализировать от текущего кадра». Для проверки всего ролика начните с первого кадра. Анализ работает в отдельном потоке, декодирует каждый кадр выбранной частоты (15/24/30 FPS) и сохраняет координаты целей и глаз. Для композиции нужны подтверждённые цели во всех рамках. Сегментация и фон в анализе не рассчитываются: они применяются при выводе и экспорте.

После анализа предпросмотр, перемотка и MP4 используют рассчитанную траекторию. Жёлтые участки под полосой перемотки и список замечаний отмечают отсутствие подтверждённой цели или слабые признаки трекера. Нажмите на участок/строку, чтобы перейти к нему. Промежутки потери не заполняются выдуманными координатами; применяется выбранное поведение при потере. Анализ повторяет решения трекера и не гарантирует правильного распознавания любого предмета. Похожий экземпляр может требовать ручной поправки. Участок до начала анализа остаётся непроверенным. Лимит — 200 000 кадров целей суммарно по рамкам; анализ можно отменить, незавершённый результат не применяется.

**Поправки по времени.** На паузе выберите нужный предмет/человека, задайте «Показывать», отступ и «Масштаб кадра», затем нажмите «Цель → Поправки по времени → Добавить / заменить поправку». Двойной щелчок по строке возвращает к её времени. Поправка выбора заново задаёт цель в свой момент; часть, отступ и масштаб плавно интерполируются между соседними поправками. Для точной перемотки после исправления выбора повторите анализ, начиная с первого нужного кадра. Без нового анализа выбор срабатывает при последовательном прохождении соответствующего момента: координаты поправки нельзя переносить на произвольный поздний кадр. Изменение выбора отменяет устаревший анализ. Поправки независимы для рамок; удаление рамки или смена категории её цели удаляет относящиеся к ней поправки.

Кнопки **«Сохранить проект ролика» / «Открыть проект ролика»** сохраняют настройки, поправки и рассчитанные координаты в JSON. Сначала откройте соответствующий видеофайл, затем проект. Размер, время изменения и хеш начала/конца файла проверяются при загрузке проекта; изменение ролика требует повторного анализа. Исходное видео и пиксели кадров в проект не включаются. PNG-маски и фоновые изображения хранятся по путям, поэтому при переносе проекта нужны и эти файлы. Проекты роликов сохраняются явно; обычные профили и сценарии по-прежнему содержат настройки, без большого кэша траекторий.

**Маски рамок.** На шаге «Рамка» раскройте «Маска и форма рамки». Доступны найденная форма, прямоугольник, овал, круг, скруглённые углы и PNG с альфа-каналом. Цвет PNG игнорируется: непрозрачные участки показывают видео, прозрачные — фон композиции. Маска растягивается на прямоугольник активной рамки; круг вписывается в него. Настройки независимы для рамок и сохраняются в профиле, сценарии и проекте. Маска ограничивает видимую область и может обрезать части цели; она не является сегментацией предмета. MJPEG/MP4 и камера получают готовое RGB-изображение с фоном, а не прозрачный видеопоток.

**Окно/экран как источник видео.** На шаге «Источник» раскройте «Захват экрана и окна», обновите список, выберите источник и нажмите «Начать захват». Используется [SCStream ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/scstream?language=objc), с исключением окон собственного процесса из захвата дисплея. Собственное окно выбрать источником нельзя. Встроенная очередь кадров ограничена, FramePilot хранит только последний ожидающий кадр; статичный экран обрабатывается по статусам кадров [SCFrameStatus](https://developer.apple.com/documentation/screencapturekit/scframestatus). Камера/экран/файл взаимно переключаются. Пробел ставит экран на паузу, «Остановить» закрывает захват. Экранный звук и выделение области экрана как отдельного источника пока не реализованы. macOS должна разрешить запись экрана; после первого разрешения может понадобиться перезапуск. Запрос сделан только по действию пользователя. Живой SCStream на этом Mac пока не проверен из-за отсутствующего разрешения; целевая частота не является измеренной частотой захвата.

**Запись выхода без OBS.** На шаге «Вывод» раскройте «Запись выходного потока» и выберите MP4. Записывается фактическое выходное изображение от файла, камеры или экрана, включая ручной чёрный кадр и поведение при сбое. Запись идёт по реальному времени: при редких входных кадрах или паузе повторяется последний выходной кадр. Разрешение и FPS фиксируются при старте; последующее изменение пропорций вписывается с полями. Нажмите «Остановить и сохранить» и дождитесь сообщения о сохранении. Используется H.264, **без звука**; для исходного звука видеофайла предусмотрен автономный экспорт. Кодирование выполняется отдельно, очередь не растёт; отставание больше двух секунд останавливает запись с ошибкой. Результат заменяет выбранный файл только после успешной финализации, исходный ролик перезаписывать нельзя.

В версии 0.13 отдельно проверена реальная OBS Virtual Camera; Android-приёмник ещё требует проверки, см. отчёт ниже.

## Рабочее пространство

В версии 0.10 интерфейс организован в четыре шага слева: **«Источник → Цель → Рамка → Вывод»**. Справа находятся настройки выбранного шага; дополнительные разделы раскрываются нажатием на заголовок. Сценарии доступны отдельной кнопкой, профили и горячие клавиши — через меню «⋯» вверху.

Три предпросмотра остаются видимыми одновременно: исходник, обработанный результат и окно назначения. Переключатель над ними или стрелка в заголовке увеличивает нужный предпросмотр. Изменение компоновки сохраняет выбранный экземпляр, область вывода и параметры обработки. Выбор лица или предмета выполняется на исходнике, выбор рамки — на изображении окна назначения.

Внизу рабочей области находятся воспроизведение, перемотка, повтор и звук. Нижняя строка показывает состояние сигнала, контроль цели и измеренные показатели обработки. Индикатор **«Локальный выход»** вверху означает работу сервера FramePilot; подключение OBS и принимающей камеры проверяется отдельно в мастере. Кнопка **«Чёрный кадр»** доступна на любом шаге.

Чтобы начать: нажмите **«Открыть видео»**, выберите цель на шаге «Цель», задайте место назначения на шаге «Рамка» и нажмите **«Подключить»**. Примеры с лицом и предметом доступны внизу левой панели. Интерфейс рассчитан на окно от 1120×740; длинные разделы прокручиваются по вертикали.

## Контроль качества отслеживания предмета

В версии 0.9 трекер хранит поворачивающуюся область исходного выделения. Проверка внешнего вида выполняется в координатах первоначального образца; сам образец не подменяется новыми кадрами. Периодическое ограниченное совмещение с образцом уменьшает накопление ошибки. Используются [оптический поток OpenCV](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html) и [преобразования координат](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html), без загрузки новых моделей или отправки видео наружу.

После краткого перекрытия нужны два согласованных кадра с разными временными отметками, прежде чем восстановится автоматическое отслеживание. Если локальный поиск находит несколько подходящих предметов, автоматический выбор останавливается: кандидаты отмечаются жёлтыми рамками `?1`, `?2` и выбираются кликом на входном видео. Кнопка подтверждения доступна только для единственного кандидата. После длительной потери (больше 1,2 с) остаётся ручное подтверждение. Исходная проверка цветов и образца применяется и при восстановлении.

Строка **«Контроль цели»** показывает: цель выбрана, устойчивые ориентиры, ограниченные ориентиры, проверка восстановления, неоднозначность или потеря. Наведите указатель для числовых подробностей: опорные точки, согласованность движения, ошибка образца, различие цветов и поворот. Это эвристические признаки трекера, **не вероятность правильного распознавания личности**. Для нескольких рамок данные независимы; в строке показана активная цель. Показатели входят в локальный HTTP-статус и отчёт мастера; кадры туда не включаются.

Поддержка поворота относится к движению жёсткого текстурированного участка в плоскости изображения. Отслеживание не гарантируется при сильном размытии, полном перекрытии, деформации, повороте предмета другой стороной и выходе за края. Неотличимые экземпляры после перекрытия нельзя надёжно различить по этому образцу. Без новой привязки «Левая половина» и другие части задаются относительно текущего окружающего прямоугольника. С включённой привязкой часть следует за четырёхугольником исходного выделения; произвольная физическая половина при вращении в 3D всё ещё не гарантируется.

Встроенный воспроизводимый контроль качества использует 450 синтетических кадров с известными координатами: поворот 0–89°, короткое/длинное перекрытие, два одинаковых экземпляра и смена внешности. Проверяются перекрытие рамок с эталоном (IoU), ложные захваты, восстановление и время работы. Эти результаты не заменяют проверку на пользовательских видео.

```sh
dist/FramePilot.app/Contents/MacOS/FramePilot --tracking-check --report "$PWD/test-results/tracking-check.json"
```

## Контроль сигнала и быстрый чёрный кадр

Под предпросмотром появился отдельный индикатор: кадры поступают, пауза/конец ролика, ожидание нового источника, сбой входа или обработки. Он следит за временными отметками кадров, поэтому неподвижная сцена не считается зависанием. Пауза и проверочная сетка приостанавливают контроль таймаута.

В разделе **«Если пропал видеосигнал»** задайте таймаут 0,5–15 с (по умолчанию 2 с) и действие: чёрный кадр либо удержание последнего изображения. Проверка выполняется каждые 250 мс. Поступление кадров и завершение обработки контролируются отдельно. При восстановлении свежего обработанного кадра выход открывается автоматически. Слишком старый результат обработки не допускается в MJPEG; поздний результат от предыдущего источника также отбрасывается. Программа не перезапускает отключённую физическую камеру автоматически: при её ошибке включите устройство заново.

При смене видео/камеры и при перемотке выдаётся чёрный кадр до первого свежего обработанного кадра из выбранного источника, независимо от настройки удержания. Это исключает показ изображения прежнего источника в период загрузки. Потеря выбранного предмета регулируется отдельной настройкой **«При потере цели»** и не считается пропажей самого видео.

Кнопка **«Чёрный кадр · ⌘⇧X»** закрывает живой выход вручную; повторное нажатие возвращает видео, если сигнал исправен. Работают чистое окно вывода, локальный MJPEG и тестовое принимающее окно. Отслеживание продолжается в фоне, выбранная цель сохраняется. Новые кадры, изменение разрешения и перезапуск локального сервера не отменяют закрытие. Горячая клавиша действует только пока активно приложение FramePilot. В мастере проверочная сетка не запускается при ручном закрытии выхода.

Эти настройки сохраняются для приложения, отдельно от профиля кадрирования. Они не меняют автономный экспорт MP4 и не останавливают запись/трансляцию в OBS. Уже переданные кадры могут оставаться в буферах принимающей программы. Контроль работает внутри FramePilot и не является внешним наблюдением за зависанием всей macOS/GUI. Состояние включено в `/api/status` и отчёт мастера без путей к видео и паролей. Реальную OBS/Android-цепочку по-прежнему нужно проверить отдельно.

## Мастер подключения

Кнопка **«Подключить»** открывает пять шагов: назначение, видеовыход, OBS, проверка приёмника и отчёт. Можно выбрать Genymotion Desktop/SaaS, BlueStacks Air, другой онлайн-сервис или приложение. Для облачного сервиса нужна его собственная поддержка камеры браузера внутри Android; при включении такой передачи выходное видео отправляется в этот сервис.

1. Откройте свой ролик и выберите объект в главном окне. Для начала задайте 720p / 30 FPS.
2. В OBS включите сервер WebSocket, введите порт и пароль в мастере. «Подготовить сцену» создаёт/обновляет только сцену FramePilot. Отдельная кнопка переключает на неё и запускает виртуальную камеру; во время записи/трансляции такое переключение блокируется.
3. Выберите OBS Virtual Camera в принимающей программе. В мастере укажите её окно либо выберите локальную OBS Virtual Camera для проверки передачи на Mac.
4. Запустите проверочную сетку. В окне приёмника выделите именно видимую область камеры. Мастер распознаёт метки текущего сеанса и меняющийся счётчик, затем определяет обрезку, зеркало и поворот 0/90/180/270°. При трёх согласующихся измерениях доступна кнопка применения калибровки. Для сильной обрезки с невидимыми метками остаётся ручная настройка.
5. Вернитесь к ролику, проверьте размещение и сохраните подключение/отчёт JSON. Сохраняются параметры видео и окна, адрес сервиса без query/fragment и порт OBS; пароль и кадры не сохраняются. При повторном открытии результаты проверки не считаются действующими автоматически.

Виртуальная камера OBS должна выдавать Program или сцену FramePilot. По [официальной инструкции Genymotion](https://support.genymotion.com/hc/en-us/articles/36992223861021-How-to-use-OBS-Virtual-Camera-with-Genymotion) для Desktop 3.10+ поддержка OBS Virtual Camera экспериментальная, а выход OBS должен быть **1280×720**. Мастер проверяет фактические параметры через OBS API, но не меняет глобальное разрешение OBS самостоятельно. Для BlueStacks Air совместимость ещё требует проверки на конкретной версии. Установка эмуляторов и облачные аккаунты не входят в приложение.

Замер сетки — время от генерации выходного кадра до наблюдения его счётчика в приёмнике. Оно включает OBS, получение кадра или снимка окна и копирование; это не задержка от сенсора до дисплея. Повторные кадры не увеличивают выборку. Захват окна ограничен 5 снимками/с, поэтому по нему **нельзя** оценить FPS Android или количество пропущенных кадров. Частота локальных событий камеры и счётчики пропусков собственного обработчика показаны отдельно. Локальная обработка измеряется до приёмника; число кадров без подтверждённой цели не является оценкой точности по эталонной разметке.

Встроенное тестовое окно проверяет сам мастер. Получение сетки через OBS Virtual Camera подтверждает передачу на Mac. Для отметки Android требуется выбранное внешнее окно с полученной сеткой и явное подтверждение пользователя, что в нём открыт именно предпросмотр камеры Android-приложения. Эти проверки не подтверждают совместимость всех приложений.

## Запуск готового приложения

Откройте [dist/FramePilot.app](./dist/FramePilot.app) двойным кликом. Python, полный Xcode и платный аккаунт Apple Developer для этой сборки не нужны: интерпретатор и библиотеки включены в приложение. Это локальная сборка с ad-hoc подписью, без Developer ID и нотарификации для публичного распространения.

Требования: Apple Silicon, macOS 14+; фактически сборка проверяется на macOS 27.2. OBS устанавливается отдельно. Можно переместить `.app` целиком в Applications; папка исходников для работы готовой сборки не требуется.

1. Нажмите **«Тестовое видео»** и **«Тестовое окно»** для встроенной проверки.
2. Для собственного файла нажмите **«Открыть видео…»** или перетащите видео в главное окно. Поддержка кодека зависит от Qt Multimedia; начните с H.264 MP4.
3. Первым выбирается самое крупное лицо. Нужное лицо можно выбрать кликом в левом предпросмотре. Статус сообщает о потере лица.
4. Пробел включает паузу/воспроизведение, Cmd+O открывает файл. Полоса времени позволяет перемотать видео. Смена настроек на паузе сразу пересчитывает выходной кадр.

### Предмет вместо лица

Выделите предмет прямоугольником на входном предпросмотре. Воспроизведение приостановится, а режим переключится на «Предмет». После проверки выбора нажмите воспроизведение. Это отслеживание внешнего вида выбранного участка, без распознавания категории предмета. Оно лучше работает с текстурными объектами при умеренном движении и изменении масштаба. Резкий поворот, смена видимой стороны, сильное изменение освещения, перекрытие или похожий соседний объект могут привести к потере/ошибке. После перемотки выделите предмет заново. Зелёная рамка обозначает подтверждённую цель; другие обнаруженные лица показываются отдельно.

### Отслеживать целый предмет, показывать его часть

Чтобы показывать выбранную часть любого отслеживаемого предмета:

1. Выделите **целый предмет** прямоугольником на входном кадре. Этот прямоугольник используется для отслеживания.
2. На шаге «Цель», в разделе «Цель и отслеживание» установите **«Показывать → Левая половина»**. Также доступны правая, верхняя и нижняя половины.
3. Для своей области нажмите **«Выделить часть внутри цели»** и выделите её внутри зелёной рамки. Воспроизведение приостановится. Синяя пунктирная рамка показывает область вывода; зелёная остаётся рамкой целого предмета.
4. Для точного размещения без дополнительных полей задайте отступ 0; выберите вписывание или заполнение рамки.
5. Установите **«Реакция → Быстрая»** и продолжите воспроизведение.

Область вывода привязана к координатам прямоугольника отслеживаемой цели и следует за его перемещением и масштабом. Она задаётся отдельно для каждой рамки, сохраняется в профилях/сценариях и применяется к экспорту MP4. Изменение области не переобучает трекер на половине предмета. Исключённая часть отрезается **до** масштабирования, поэтому она не появляется в свободных полях при другом соотношении сторон выхода.

Это часть изображения, а не сегментация произвольного предмета. Окружающий фон внутри выбранного участка сохраняется. По умолчанию «левая половина» остаётся левой половиной текущего окружающего прямоугольника. В режиме «Часть следует за поворотом» она следует за исходными осями выделенной поверхности; универсальная привязка конкретной физической половины при вращении в 3D не реализована.

**«Тест предмета»** открывает встроенный синтетический ролик с движущимся и меняющим масштаб яблоком, выбирает целую цель и вывод её левой половины в быстром режиме. Он служит для воспроизводимой проверки цепочки. Автоматический выбор цели в этом ролике использует известные координаты тестового изображения; это не детектор яблок и не проверка на вашем реальном видео.

### Автоматический переход между частью и целым предметом

1. Выделите целый предмет и выберите часть, как описано выше.
2. Включите **«Авто: выбранная часть ↔ целая цель»**.
3. Выберите правило: показывать целиком, когда рамка **больше** либо **меньше** порога.
4. Задайте «Порог площади рамки» в процентах окна назначения. Кнопка **«Текущая рамка — порог»** берёт площадь текущей рамки за границу. При необходимости верните автоматический поиск рамки кнопкой «Автопоиск».

Например, при пороге 20% и защите от переключений 10% выбранная часть сменяется целым видом при увеличении рамки до 22% окна. Целый вид сохраняется, пока рамка не уменьшится ниже 18%. Внутри этого коридора сохраняется предыдущий вид; при первом включении внутри коридора используется выбранная часть. Правило «меньше порога» работает в обратную сторону. Это настраиваемое правило по геометрии: программа не распознаёт смысл требований чужого приложения.

Изменение одного размера окна целиком при сохранении пропорций рамки не меняет её относительную площадь. В режиме «Камера / видеослот» правило также использует рамку принимающего окна, хотя выходное разрешение камеры может оставаться постоянным.

Переход по умолчанию занимает 0,12 секунды. Можно задать 0 для мгновенного переключения или увеличить длительность. Переход работает и на паузе. Выбранный экземпляр продолжает отслеживаться целиком; его не нужно выделять повторно. Каждая рамка композиции имеет свои правила. Настройки сохраняются в профилях и сценариях; старые профили загружаются с выключенным автоматическим переключением.

Вид «целиком» вписывает прямоугольник цели и защищает его от обрезки при движении. Для этого дополнительные приближение и смещение постепенно снимаются, режим заполнения переходит во вписывание, удержание глаз не применяется. Для овальной рамки оставляется запас по углам. Основная калибровка видимой области и зеркала сохраняется. Полный предмет должен присутствовать в исходном видео; отсутствующие части не восстанавливаются.

Автоматический режим запрашивает поиск рамки с интервалом 120 мс. Обнаружение по-прежнему требует подтверждения, а захват окна, обработка, OBS и эмулятор добавляют задержку. Работа с конкретным эмулятором/онлайн-сервисом пока не проверена.

В замере версии 0.6 на Apple M5: 180 синтетических кадров, полный холст 1280×720, шесть переключений размера рамки, цель подтверждена в 180/180 кадров. Средняя обработка — 4,88 мс, p95 — 7,52 мс, JPEG — 0,88 мс; вместе в среднем 5,76 мс. Площади рамок в этом тесте меняются, поэтому это отдельный сценарий от замера фиксированного камерного выхода ниже. Замер не включает декодирование, интерфейс, передачу, OBS, эмулятор и сеть. [Отчёт автоматического режима](./test-results/benchmark-0.6-adaptive.json).

### Быстрая реакция

В быстром режиме сглаживание движения сокращается до 15 мс, увеличиваются пределы перемещения/масштаба и интервал запроса поиска рамки уменьшается с 250 до 120 мс. Настройка обычной плавности в этом режиме не применяется. Автопоиск по-прежнему требует двух согласующихся обнаружений; захват окна, OBS, браузер, эмулятор и сеть добавляют задержку. 120 мс — интервал запроса, а не обещанная задержка обнаружения.

Предмет отслеживается по движению характерных точек с проверкой исходного образца и цвета на каждом кадре. При недостатке точек используется поиск образца с несколькими масштабами. Исходный образец не заменяется текущим изображением, чтобы уменьшить постепенный уход на фон. Низкая текстура, смаз движения и похожие предметы остаются ограничениями.

На Apple M5: 180 кадров синтетического ролика, выход 1280×720, вывод левой половины — подтверждено 180/180 кадров, среднее время отслеживания/рендеринга 7,19 мс, p95 8,06 мс, JPEG 1,05 мс. Сравнение с поиском образца на каждом кадре в том же тесте — 17,61 мс обработки. Отчёты: [ускоренный режим](./test-results/benchmark-0.5-object.json), [поиск образца](./test-results/benchmark-0.5-object-template.json). Это замер после прогрева, без декодирования, интерфейса, передачи, OBS, эмулятора и сети. Он не измеряет задержку всей цепочки и не гарантирует такой же результат на реальном ролике.

### Человек и восстановление цели

В поле «Отслеживание» доступны «Человек по пояс» и «Человек целиком». Apple Vision находит прямоугольник человека; нужного человека можно выбрать кликом. Для полного тела нужен подходящий исходный кадр: отсутствующие части тела программа не дорисовывает. Удержание глаз применяется только к режиму лица.

После потери лица/человека программа ищет похожие варианты по внешнему виду. После длительной потери предмета выполняется поиск шаблона по всему кадру с несколькими масштабами. Найденные варианты выделяются оранжевым. Проверьте вариант и нажмите «Подтвердить найденную цель» для первого кандидата либо кликните по нужному. При подтверждении воспроизведение приостанавливается. Это не распознавание личности: похожие люди/предметы могут давать ложные совпадения. При отсутствии подходящего кандидата выделите цель заново.

### Вход с камеры

Нажмите «Обновить камеры», выберите встроенную/внешнюю камеру и нажмите «Включить камеру». Разрешите доступ к камере в macOS. До этого действия устройство не включается. Для первого запроса разрешения предпочтительна готовая `.app`: описание доступа включено в её Info.plist согласно [документации Qt](https://doc.qt.io/qt-6/qcamerapermission.html).

Камерный поток проходит через то же отслеживание, кадрирование, удаление фона и OBS. Пробел приостанавливает камеру с остановкой устройства; «Выключить камеру» освобождает её. На этом входе нет перемотки; для записи доступны OBS и раздел «Запись выходного потока» в FramePilot. Автономный экспорт MP4 обрабатывает только видеофайлы. Проверки камеры с подставными кадрами и разрешениями автоматизированы; физическое устройство и выдачу разрешения нужно проверить на вашем Mac.

### Положение глаз и масштаб

В режиме лица можно включить «Удерживать глаза по высоте» и задать уровень глаз от 0 до 1 по высоте рамки. Используются настоящие ориентиры Apple Vision, обновляемые периодически. Если глаза не найдены, программа центрирует лицо и сообщает об этом. «Предел приближения» ограничивает масштаб относительно исходного общего плана; поэтому при низком пределе лицо может занимать меньшую часть рамки. Режим «Вписать» учитывает отступы вокруг лица.

Исходная Python-версия также запускается через [Start FramePilot.command](./Start%20FramePilot.command).

## Поиск рамки

Тестовое принимающее окно меняет положение/размер рамки каждые 8 секунд. Рамка определяется по пикселям; ее координаты не передаются детектору из шаблона.

Для сторонней программы нажмите **«Обновить окна»**, разрешите запись экрана в настройках macOS и выберите окно назначения. Если macOS требует перезапуска после выдачи разрешения, перезапустите FramePilot. Получение списка окон и захват не блокируют видеопроцессор.

- **Обычные рамки** — контрастные прямоугольники и овалы.
- **Тонкие / слабоконтрастные** — усиление локального контраста и более чувствительный поиск. Этот режим может находить лишние элементы интерфейса.
- **Область поиска** — нажмите кнопку и выделите в предпросмотре «Окно назначения» область, где следует искать рамки. **«Всё окно»** снимает ограничение.
- При нескольких кандидатах они пронумерованы. Клик по кандидату выбирает его; кнопка **«Другая рамка»** переключает варианты.
- Обычное выделение мышкой задает ручную рамку. **«Автопоиск»** возвращает автоматический режим.

Новая рамка принимается после двух согласующихся обнаружений. Изменения менее 0,3% размера окна игнорируются, чтобы уменьшить дрожание и пересоздание выхода. При исчезновении рамки сохраняется последнее подтвержденное размещение и выводится статус.

Декоративные, перекрытые, наклоненные и произвольные контуры не гарантируются. Детектор распознает геометрию, а не смысл элементов чужого интерфейса. Среди нескольких похожих областей может потребоваться выбор пользователя.

## Два способа размещения

**Камера / видеослот** — принимающая программа сама помещает изображение камеры в свой слот. FramePilot центрирует лицо в изображении камеры; координаты слота не применяются вторично. По желанию можно включить **«Пропорции по найденной рамке»**. По умолчанию выход фиксированный, что упрощает OBS.

**Полный холст** — найденная рамка задает положение и размер видео внутри всего выходного кадра. Снаружи выбранный фон композиции. Пропорции холста и принимающей поверхности нужно согласовать; координаты относятся к содержимому захваченного окна.

### Несколько рамок

«Добавить рамку» включает композицию из двух рамок; повторное нажатие добавляет третью/четвёртую. Выберите активную рамку в списке, затем задайте её цель на входном видео. Для каждой независимо сохраняются цель, положение, форма, отступ, режим заполнения, уровень глаз и предел масштаба. Обычное выделение в предпросмотре «Окно назначения» меняет положение активной рамки. Сброс отслеживания действует только на активную цель.

«Рамки из предпросмотра» создаёт композицию из первых четырёх найденных рамок. При включённом автопоиске новые позиции сопоставляются с предыдущими по пересечению и стабилизируются. Если совпадения нет, позиция сохраняется; резкая перестановка одинаковых рамок может потребовать ручного выбора. При наложении рамок последняя в списке располагается сверху.

Композиция выдаёт **один общий холст**, поэтому нельзя направить четыре независимые виртуальные камеры в четыре поля чужой программы. Принимающая программа должна показывать общий холст с нужными пропорциями. Для независимых полей понадобятся отдельные видеовыходы, которых в этой версии нет.

### Удаление и замена фона

«Удалить фон у людей» включает [сегментацию человека Apple Vision](https://developer.apple.com/documentation/vision/vngeneratepersonsegmentationrequest). Выберите цвет либо PNG/JPEG в группе «Фон композиции» на шаге «Цель». Картинка заполняет холст с сохранением пропорций и обрезкой лишнего. Прозрачные участки PNG смешиваются с выбранным цветом. Это задний фон, а не передняя накладка поверх человека.

В режиме баланса маска пересчитывается через один обработанный кадр, в точном — каждый кадр. Несколько рамок используют одну общую маску. Контуры волос, быстрое движение и перекрытия могут давать артефакты. Маска выделяет **всех видимых людей**, поэтому это не гарантированная изоляция одного человека среди пересекающихся людей. Для произвольных предметов удаления фона нет: используется исходное изображение внутри рамки.

Для обычного кадрирования достаточно прямоугольника цели; сегментация нужна именно для вырезания силуэта. Маска используется внутри программы. MJPEG, OBS Virtual Camera и текущий MP4 передают непрозрачное видео с уже подставленным фоном.

### Сценарии и горячие клавиши

Сохраните именованный сценарий в правой панели. Он включает источник, композицию, настройки фона/кадрирования, профиль окна и, для файла, время последнего обработанного кадра и подтверждённые цели. Применение сценария восстанавливает ролик с этой позиции. Файл остаётся по своему пути; он не копируется в профиль. При недоступном файле переключение отменяется. Для камеры сохраняется устройство; цели выбираются заново. При запуске приложения сценарии не исполняются автоматически.

Cmd+1…4 выбирают активную рамку; Cmd+Option+1…4 применяют первые четыре сохранённых сценария; Cmd+Shift+B переключает вырезание людей; Cmd+Shift+G — сетку; Cmd+Shift+K — камеру; Cmd+E — экспорт. Комбинации действуют в окнах FramePilot. Полный список открывает кнопка «Горячие клавиши».

## Калибровка и профили окон

Нажмите «Обрезка, зеркало, положение…». Укажите проценты краев изображения камеры, которые обрезает принимающая программа, включите компенсацию ее зеркалирования при необходимости. Можно задать дополнительный масштаб и смещение в пределах рамки; положительное смещение X перемещает объект вправо в моделируемом принимающем изображении, включая случай зеркалирования.

«Проверочная сетка вместо видео» приостанавливает ролик и выводит сетку с отметками LEFT/RIGHT/TOP/BOTTOM, в том числе в OBS. По ней можно сравнить фактическую обрезку в принимающей программе. После проверки выключите сетку. Экспортируется видео, а не сетка.

«Предпросмотр с учетом приемника» показывает модель заданной обрезки/зеркала. Чистое окно и OBS при этом получают исходный обработанный видеовыход с компенсацией. Внутреннее тестовое окно также моделирует параметры приемника. Калибровка действует в режиме «Камера / видеослот»; для полного холста используется размещение по координатам рамки.

Это ручная калибровка, а не автоматическое измерение неизвестного приложения. Фактическую обрезку/масштабирование нужно сравнить с выбранной программой.

Кнопка «Запомнить для окна» сохраняет текущие настройки и калибровку для выбранного окна. При повторном выборе окна с тем же идентификатором приложения и заголовком профиль применяется автоматически. Если заголовок изменился, профиль можно выбрать вручную в списке. Профили хранятся локально. Нажатие «Удалить» удаляет выбранную запись. Само окно назначения автоматически при запуске не захватывается.

## Автоматическая настройка OBS

1. Откройте OBS. В меню **Сервис / Tools → Настройки сервера WebSocket / WebSocket Server Settings** включите сервер. Посмотрите порт (обычно `4455`) и пароль.
2. В FramePilot нажмите **«Настроить OBS автоматически…»**, введите порт и пароль.
3. Программа создаст отдельную сцену **FramePilot** и источник **FramePilot Video**, настроит локальный адрес, размер браузерного источника и впишет его в текущий холст OBS с сохранением пропорций.
4. По умолчанию активная сцена и виртуальная камера не переключаются. Если нужно сделать это сразу, поставьте в диалоге галочку **«Переключить OBS на FramePilot и включить виртуальную камеру»**.
5. В принимающей программе выберите **OBS Virtual Camera**.

Пароль используется только для текущего подключения и не сохраняется в профиль или настройки. Мастер подключается только к `127.0.0.1`. Общий размер сцены OBS не меняется. Существующий одноименный источник с чужим содержимым не перезаписывается: переименуйте его и повторите настройку.

В настройках виртуальной камеры OBS должен быть выбран вывод **Program** либо сцена **FramePilot**. Если раньше для камеры был выбран другой конкретный источник, одно переключение активной сцены не изменит эту настройку.

После подключения соединение сохраняется: FramePilot периодически проверяет состояние OBS/виртуальной камеры и автоматически синхронизирует размер и FPS нашего источника при их изменении. Изменения объединяются, чтобы не накапливать очередь команд. Постоянный опрос не перезапускает источник. Синхронизация не переключает текущую сцену, не меняет общий размер холста и не включает скрытый пользователем источник. При потере соединения, удалении или замене источника синхронизация останавливается; выполните подключение заново. Пароль после входа удаляется из объекта клиента и на диск не записывается.

Для постоянного размера можно оставить автоматические пропорции выключенными. OBS и принимающая программа могут дополнительно обрезать или зеркалить камеру — проверьте их параметры.

## Ручное подключение OBS

1. В FramePilot нажмите **«Вывод в OBS через браузер»**. Адрес копируется в буфер обмена; он также показан в доступном для выделения поле.
2. В OBS добавьте источник **Браузер**, вставьте адрес, укажите ширину/высоту как у выхода FramePilot. Локальный файл выключен.
3. Впишите источник в сцену с сохранением пропорций и запустите **OBS Virtual Camera**.

Исходный порт FramePilot — `18765`. При занятом порте выбирается свободный; фактически выбранный порт сохраняется для следующего запуска. Всегда используйте адрес из интерфейса. Кнопка **«Открыть адрес»** открывает именно собственный активный сервер. Проверить его можно по `/api/status`: ответ содержит `application: FramePilot` и версию.

Сервер слушает только loopback. Кадры передаются как локальный MJPEG с JPEG quality 88; аудио и прозрачность не передаются. Видеостраница повторно подключается при перезапуске сервера. **«Остановить выход»** закрывает локальный сервер. FramePilot должен оставаться открытым.

Альтернатива: **«Открыть чистое окно вывода»**, затем захват окна **FramePilot Output** источником «Захват экрана macOS» в OBS. В этом случае обрежьте заголовок и поля окна.

## Надежность и настройки

- Видеопроцессор, захват окон и настройка OBS работают в отдельных потоках. В обработке не более одного кадра: при перегрузке новые кадры пропускаются, очередь задержки не накапливается.
- После смены видео, перемотки, выбора лица или настроек устаревшие результаты не выводятся в предпросмотр и OBS.
- Время отслеживания привязано к видеоролику, а не длительности паузы. Поздние кадры после паузы игнорируются; при перемотке ожидается кадр около нужной отметки.
- Повторное обнаружение лица использует пространственное совпадение и цветовую гистограмму. Это не биометрическая идентификация: похожие/пересекающиеся лица могут спутаться.
- Краткое перекрытие допускает повторный поиск до 1,2 секунды с момента наблюдаемой потери по времени видео. Пропущенные декодером кадры сами по себе не считаются наблюдаемым отсутствием цели. После долгой потери требуется подтверждение предложенного кандидата или повторный выбор.
- При потере цели можно удержать последний кадр цели, показать исходный план в её рамке или скрыть цель, оставив фон композиции.
- Настройки кадрирования/калибровки, выбранная часть цели, правила автоматического переключения, профили окон, сценарии, область поиска, последний каталог видео, размер окна и фактический порт сохраняются автоматически в конфигурационном каталоге FramePilot. Видео, скриншоты чужих окон и пароли не сохраняются. Профили JSON можно экспортировать/импортировать; версии 1–6 поддерживаются.
- FPS и время обработки показываются в интерфейсе. Это не сквозная задержка через OBS и приложение назначения. Доступны 720p/1080p/портретный режим и лимит 30/24/15 FPS.

Замер версии 0.4 на текущем Apple Silicon, 120 движущихся кадров после прогрева, выход 1280×720: одна рамка лица без сегментации — в среднем 7,08 мс, p95 10,85 мс; две рамки лица с общей маской в режиме баланса — 29,61 мс, p95 43,81 мс. Отчёты: [одна рамка](./test-results/benchmark-0.4-single.json), [две с маской](./test-results/benchmark-0.4-scene.json). Замер включает отслеживание и рендеринг, исключает декодирование, интерфейс, JPEG/OBS и приёмник. Он не гарантирует 30 FPS всей цепочки, особенно для четырёх рамок, точной маски и 1080p. При нагрузке уменьшите FPS/разрешение или отключите сегментацию.

## Границы этой версии

Собственная системная виртуальная камера, поиск предметов по тексту и детектор категорий произвольных предметов пока не реализованы. Произвольный предмет можно отслеживать после ручного выделения. Источники — файл, физическая камера и новый поток SCStream выбранного экрана/окна; живой экранный захват ещё требует реальной проверки после выдачи разрешения macOS. Прозрачного видеовыхода и независимых потоков для каждой рамки нет.

## Экспорт MP4

Нажмите «Экспорт MP4» либо «Сохранить обработанный MP4…» в правой панели. Выберите 30/24/15 FPS, начало отрезка и сохранение исходного звука. Затем задайте путь назначения. Формат — H.264/yuv420p в контейнере MP4; при наличии звука он кодируется в AAC. Отсутствие аудио не является ошибкой. Исходный короткий звук дополняется тишиной до конца видео.

В режиме лица экспорт с начала автоматически выбирает самое крупное лицо первого кадра. Экспорт с текущего кадра использует выбранное лицо, если оно подтверждено. В режиме предмета экспорт начинается с кадра первоначального выделения предмета. После перемотки предмет требуется выделить заново.

Композиция из нескольких рамок экспортируется с последнего обработанного кадра вместе с подтверждёнными целями всех рамок, выбранным фоном и сегментацией. Для каждой рамки с предметом перед экспортом нужно подтвердить цель.

При автоматическом переключении MP4 фиксирует выбранный правилом конечный вид на момент запуска экспорта, включая состояние защиты от переключений. Он не записывает последующие изменения геометрии внешнего окна. Для записи живых изменений рамки используйте запись в OBS.

Экспорт обрабатывает каждый кадр выходной частоты отдельно от живого воспроизведения. Для видео с переменной частотой формируется постоянная выбранная частота. Используется тот же рендеринг и снимок настроек на момент начала экспорта, включая калибровку; дальнейшее изменение интерфейса на текущий экспорт не влияет. Обработка может занять больше реальной длительности видео. FFmpeg включен в готовую сборку, интернет не требуется.

Экспорт можно отменить. Сначала записывается временный файл в выбранной папке; файл результата заменяется только после успешного завершения. Исходный ролик перезаписывать нельзя. При ошибке/отмене существующий файл результата сохраняется, временный удаляется.

Для вставки в стороннее приложение оно должно принимать виртуальную камеру либо другой совместимый источник. FramePilot не изменяет произвольные элементы чужой программы. Автоматический поиск рамки не гарантирует, что принимающая программа покажет камеру без дополнительной обрезки.

## Разработка и сборка

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -e '.[dev,build]'
.venv/bin/python -m framepilot --demo --sample --obs
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests tools packaging
.venv/bin/python tools/benchmark.py --frames 120
.venv/bin/python tools/benchmark.py --frames 120 --slots 2 --cutout
.venv/bin/python tools/benchmark_objects.py --frames 180
.venv/bin/python tools/benchmark_objects.py --frames 180 --template-only
.venv/bin/python tools/benchmark_objects.py --frames 180 --adaptive
```

Сборка готового приложения: [Build FramePilot.command](./Build%20FramePilot.command). Либо:

```sh
PYINSTALLER_CONFIG_DIR="$PWD/.build/pyinstaller-cache" .venv/bin/python -m PyInstaller --noconfirm --workpath .build/pyinstaller FramePilot.spec
dist/FramePilot.app/Contents/MacOS/FramePilot --self-test --report "$PWD/test-results/bundle-check.json"
codesign --verify --deep --strict dist/FramePilot.app
```

Самопроверка создает тестовый ролик, проверяет настоящее обнаружение лица, глаз и верхней части тела, рамку из пикселей тестового окна, две независимые рамки, сегментацию человека, сохранение сценария, локальный видеовыход и экспорт H.264 MP4 из собранного приложения. Затем проверяет воспроизведение синтетического ролика с отслеживанием целого предмета и выводом половины, после чего меняет размеры рамки и проверяет автоматический переход часть → целиком → часть на паузе с сохранением той же цели. В конце проверяется мастер: сетка проходит через внутреннее принимающее окно и считывается из его пикселей. Это не тест OBS. Самопроверка сохраняет отчет и снимок интерфейса, затем закрывает приложение. Физическая камера не включается; разрешение на захват внешних окон не запрашивается. Для работы без видимых окон используйте переменную `QT_QPA_PLATFORM=offscreen`. В 0.13 дополнительно проверяются чтение JPEG, прозрачность PNG, лицо на фото, сохранение PNG/JPEG, смена рамки и запись статичного источника в MP4.

[requirements-macos.lock](./requirements-macos.lock) фиксирует установленное окружение Python 3.13, включая инструменты тестирования/сборки. Для воспроизведения: установить этот файл через pip, затем `pip install --no-deps -e .`.

Автоматически проверяются геометрия, стабилизация границы, слабый контраст/область поиска, потеря и восстановление цели, движение/масштаб и другая внешность на прежних координатах, перемотка и пауза, профили, занятый порт, MJPEG и WebSocket-протокол мастера OBS. Проверяется также сохранение выбранной части при всех сочетаниях поворота и зеркалирования, отбрасывание старых измерений, восстановление видео и остановка потоков при закрытии мастера. Протокол OBS проверяется на тестовом ответчике; это не подтверждает реальную передачу камеры.

Проверка сборки **0.12** на этом Apple M5: **198 автотестов** прошли за **28,19 с**, самопроверка готовой `.app` — за **11,52 с**, подпись проверена `codesign --verify --deep --strict`. Подтверждены семь сочетаний контейнеров/кодеков из таблицы выше: для каждого получен кадр Qt, прочитан кадр FFmpeg и экспортированы шесть кадров. Из готовой сборки выполнена очередь двух экспортов, проверено автосохранение файлового сеанса. Проверка поверхности использует 45 кадров синтетической жёсткой карточки с поворотом до 88°: исключённый цветной маркер не попал в выход. Автотесты дополнительно проверяют сохранение осей части при временной поправке, восстановлении, зеркале и четырёх поворотах приёмника; восстановление остаётся на паузе. Сохраняются прежние проверки анализа, масок, звука при экспорте, записи, сигнала и остановки потоков. [Отчёт сборки](./test-results/bundle-check-0.12.json), [автотесты](./test-results/tests-0.12.log), [снимок интерфейса](./test-results/interface-0.12.png). Это функциональные проверки на локальных тестовых роликах, без гарантии всех файлов каждого формата. Реальный SCStream не захватывался без разрешения macOS; физическая камера и OBS/Android остаются непроверенными.

Отдельный замер новой привязки: вход 640×360, выход 1280×720, левая половина вращающейся карточки, по 100/100 подтверждённых кадров в обычном и быстром режимах. После десяти кадров прогрева обычный режим: обработка в среднем **12,05 мс**, p95 **13,30 мс**, с JPEG **13,04 мс**. Быстрый режим: обработка **12,92 мс**, p95 **14,81 мс**, с JPEG **13,96 мс**. Минимальный IoU — 0,9907. Эти значения включают трекер, рендеринг и оценку кадрирования, исключают декодирование, UI, OBS, сеть и эмулятор; это не задержка всей цепочки. [Отчёт замера поверхности](./test-results/benchmark-surface-0.12.json).

Отдельный `--tracking-check` выполнен **из готовой сборки 0.9**: все пять сценариев прошли, ложных подтверждений в них не было. Поворот: 90/90 подтверждённых кадров, минимальный IoU 0,9864. Краткое перекрытие: пять скрытых кадров и один кадр проверки восстановления, затем возврат на 26-м кадре. В сценариях двойников, длительного перекрытия и смены внешности после потери автоматический захват оставался закрыт, как и требуется условиями проверки. [Отчёт контроля качества](./test-results/tracking-quality-0.9.json). Это проверка синтетического плоского текстурированного объекта, а не доказательство точности на любом предмете.

Отдельный синтетический замер версии 0.9: 180/180 подтверждённых кадров, шесть смен вида; обработка в среднем 5,51 мс, p95 8,75 мс, с JPEG в среднем 6,48 мс. [Отчёт замера](./test-results/benchmark-0.9-adaptive.json). Эти значения исключают декодирование, UI, OBS, эмулятор и сеть; их нельзя считать задержкой готовой Android-цепочки.

Реальная проверка OBS Virtual Camera выполнена в сборке **0.13.0** с OBS **33.0.1**: сетка текущего сеанса прошла через браузерный источник и вернулась через системную виртуальную камеру в Qt. Подтверждена 31 уникальная наблюдаемая сетка. Медиана наблюдаемой задержки — 88,26 мс, p95 — 328,05 мс; это замер от выпуска сетки до её наблюдения с учётом частоты проверки, а не задержка сенсора. Источник, прежняя сцена и состояние камеры восстановлены после теста. [Отчёт камеры OBS](./test-results/obs-camera-0.13.json). Отдельно подтверждены движущиеся кадры видео внутри браузерного источника OBS. Конкретный эмулятор и принимающее Android-приложение ещё требуют проверки.

Для отдельной явной проверки из готовой сборки доступно `--obs-self-test --report /абсолютный/путь/report.json`. Этот режим требует уже работающий и свободный от записи/трансляции OBS с включённым WebSocket, временно активирует сцену FramePilot и OBS Virtual Camera, получает сетку через Qt-камеру, затем возвращает прежнюю сцену, настройки источника и состояние камеры. Разрешение macOS на камеру и расширение OBS должны быть доступны; тест не подтверждает Android. Пароль читается локально из конфигурации OBS и не включается в команду/отчёт. Обычный запуск приложения конфигурацию OBS не читает для авторизации: пароль вводится в мастере.

## Приоритеты следующего этапа продукта

1. Проверить реальные пользовательские ролики и один согласованный эмулятор/Android-приёмник: перекрытия, повторное появление, цикл ролика, изменение света и полную задержку. Локальная OBS Virtual Camera проверена в 0.13; внешняя цепочка в Android ещё не принята.
2. Проверить новый живой захват экрана/окна после выдачи разрешения macOS: размер окна, пауза, закрытие источника, фактические FPS и задержка. Добавить выбор области экрана и звук после этой проверки.
3. Расширять новую привязку части за пределы поворота жёсткой поверхности в плоскости кадра: отдельно проверить перспективу, деформации и поворот в 3D.
4. Добавлять локальное обнаружение по описанию и выделение предметов из фона после выбора моделей, проверки лицензий и измерения скорости на M5. Ручной трекер остаётся отдельным способом выбора.
5. Проверить удобство нового интерфейса на пользовательских роликах и конкретном принимающем приложении; уточнять рабочий процесс по результатам этих проверок.
