# Проверка FramePilot 0.15.1

Последняя повторная проверка: [FramePilot 0.15.2](./AUDIT-0.15.2.md). Ниже сохранён отчёт предыдущего выпуска.

Дата: 11 ноября 2026. Проверялись исходники и самостоятельное macOS-приложение. Windows-сборка в этой среде не выполнялась.

Устройство проверки: Mac17,2, Apple M5, 16 ГБ памяти, macOS 27.2.1, arm64. Подробные журналы доступны в рабочей папке проекта; в Windows-архив включён этот отчёт без журналов macOS.

## Исправленные ошибки

| Ошибка | Исправление |
| --- | --- |
| Закрытие во время обработки пропускало последнее выделение в автосохранении | Перед снимком сеанса завершается текущая обработка и ожидающий перерендер. Результат забирается из последовательного рабочего потока без вложенного цикла Qt. |
| Несколько копий приложения использовали один временный файл настроек | Для каждой записи создаётся отдельный временный файл, затем выполняется атомарная замена. |
| Исключение при получении списка окон Windows не доходило до интерфейса | Выдаётся понятное сообщение и пустой список вместо необработанного исключения. |
| После остановки захвата Qt мог повторять старое изображение как живое | Проверяется активность захвата. В Windows дополнительно проверяются существование окна, процесс-владелец и свёрнутое состояние. Неизменяющееся изображение активного окна по-прежнему допустимо. После ошибки захват можно возобновить. |
| Одновременное сохранение исходных имён камеры могло перезаписать резервную копию | Чтение, объединение и запись копии защищены межпроцессной блокировкой. |
| Переименованная второй раз камера OBS могла пропасть из мастера подключения | Сохраняется подтверждённый идентификатор устройства, даже если Qt продолжает показывать старое название. |
| Диагностика OBS в Windows искала настройки в каталоге macOS | Общая функция выбирает путь по платформе, включая `%APPDATA%` Windows. |
| Ошибка чтения исходного состояния OBS могла запустить восстановление неполного снимка | Восстановление выполняется только после полного чтения состояния и начала настройки. Ошибка восстановления отдельно отражается в отчёте. |

Первые семь ошибок воспроизведены до исправления в `test-results/audit-reproduced.log`; ошибка неполного снимка OBS — в `test-results/audit-obs-reproduced.log`. Добавлено 13 регрессионных тестов. Во время проверки исправления закрытия найдено падение при повторном входе в цикл Qt; этот вариант заменён, в выпущенную сборку он не входит.

## Результаты проверки

- Полный набор: **275 passed in 39.81s** — [журнал](./test-results/audit-full-native.log).
- Ruff: проверка ошибок и форматирования прошла для всех 83 Python-файлов; компиляция исходников прошла.
- Готовое `.app`: самопроверка прошла за **11,91 с** — [отчёт](./test-results/bundle-check-0.15.1.json). Проверены загрузка видео и JPEG/PNG, Apple Vision, глаза, сегментация человека, две независимые рамки, сопровождение выбранной части предмета, автоматический переход часть/целое, сохранение сценария, локальный выход, чёрный кадр, анализ ролика, экспорт H.264 и запись фактического выхода.
- Переносимый путь с принудительным **YuNet** в готовом Mac-приложении: прошёл за **0,86 с** — [отчёт](./test-results/portable-check-0.15.1.json). Это проверка общего движка, а не Windows API.
- Установочный DMG проверен `hdiutil verify`. Подпись `.app` проверена `codesign --verify --deep --strict`. Приложение запущено прямо с образа, подключённого только для чтения, с системным `PATH` без Python проекта: переносимая самопроверка прошла за **1,03 с** — [отчёт](./test-results/dmg-portable-check-0.15.1.json). Windows ZIP проверен на целостность и наличие файлов сборки; в нём нет кэшей Python.
- Реальная цепочка **FramePilot → OBS 33.0.1 → OBS Virtual Camera → получатель Qt**: прошла — [отчёт](./test-results/obs-camera-0.15.1.json). Подтверждено 127 уникальных тестовых кадров; медиана наблюдаемой задержки 79,66 мс, 95-й процентиль 104,76 мс. Это задержка тестового рисунка от отправки до наблюдаемого возврата с учётом выборки, не задержка сенсор–экран. Запись и трансляция не включались. Сцена, источник, состояние камеры и исходный файл настроек WebSocket восстановлены.
- Движение, перекрытие, исчезновение и похожие кандидаты проверяются существующими тестами трекинга на контролируемых примерах. Эти результаты не являются оценкой качества на любых пользовательских видео.

## Ограничения подтверждения

Проверка Windows выполнена на Mac через подставные интерфейсы реестра, UAC и захвата. Реальная установка Windows 11 x64, запуск EXE, работа Win32/Qt, запись имён в реестр и окно UAC требуют проверки на Windows. Архив Windows содержит исходники и команды сборки, не готовый EXE.

Физическая камера, полноценный захват экрана с разрешениями macOS, Genymotion, BlueStacks, онлайн-эмуляторы и принимающие Android-приложения в этом прогоне не проверялись. Самопроверка связывает API захвата, но не выдаёт это за успешный поток экрана. Возврат из OBS Virtual Camera проверен локально, без эмулятора.

Не заявляется распознавание любого произвольного предмета или рамки. Для предмета используется ручное выделение и сопровождение; рамки определяются по геометрии изображения, с возможностью ручного выбора. Тесты подтверждают проверенные случаи и не гарантируют отсутствие всех ошибок.

## Повторная проверка

В рабочей среде macOS:

```sh
.venv/bin/pytest -q
.venv/bin/ruff check src tests tools
.venv/bin/ruff format --check src tests tools
dist/FramePilot.app/Contents/MacOS/FramePilot --self-test --report test-results/recheck-mac.json
FRAMEPILOT_VISION_BACKEND=yunet dist/FramePilot.app/Contents/MacOS/FramePilot --portable-self-test --report test-results/recheck-common.json
```

Для теста реального OBS предназначен `tools/check_obs.py`. Он требует установленного OBS и отсутствия уже запущенного экземпляра; временно меняет WebSocket-настройки и восстанавливает исходный файл после завершения. Отчёты не содержат пароль.
